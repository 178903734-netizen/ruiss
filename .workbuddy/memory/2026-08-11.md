# 2026-08-11 — 根治 Mac 跨屏双滚 + Dock 隔空触发（第三次重做，找到真正根因）

## 之前两次为什么没修好（教训）
- 4e4ffc5（8/8）：warp 屏幕中心断坐标镜像 + 吞移动无 delta 累积（对端卡住）+
  释放不恢复 → 用户"好像改了东西"被回退。
- 55e86cc（8/10）：补齐全套副作用（SOURCE_VIRTUAL_POS、warp_cursor_cross 避热区、
  释放恢复、Warp 先于 TakeControl），方向全对——但 tap 还在 HID 层。
- 6618b71 实验（8/11）：HID 层 tap return None **拦不住 momentum**（实测 Mac 应用
  照样滚）。momentum 由 WindowServer 内部合成、绕过 HID tap 的拦截路径，只有
  Session 层（WindowServer 对外派发层）能拦。→ 55e86cc 没动 tap 层 = 双滚根因未除。

## 本次改动（对照 55e86cc 只多一层）
1. tap 捕获层 HID → **Session**（mac.rs CGEventTap::new 的 location）。
2. 防回环早退 `pid != 0` → `pid == 本进程 pid`（OWN_PID OnceLock）。
   与 Synergy/InputLeap 同款（它们就是 Session tap + pid 识别自身注入）。
3. Source 跨屏吞 MouseMoved/Dragged + SOURCE_VIRTUAL_POS delta 累积（对端镜像不断）。
4. warp_cursor_cross：y 避 Dock/菜单栏热区 + 播种虚拟位置（x 仍在对侧边缘）。
5. set_local_input_blocked(false) 时 warp 回最后虚拟位置（释放恢复）。
6. arbiter：Warp 排 TakeControl 前；win.rs 加同名桩；lib.rs Warp 改调 cross 版。
7. 保留 [MAC-SCROLL-DIAG] 全量滚动日志（blocked||sink 时打 pid/dx/dy），双机验证后可删。

## 需 Mac 实机验证（关键风险点）
- Session tap 下【自有注入事件 pid 是否仍 == 本进程 pid】：Sink 注入（win→mac）
  依赖它放行。若注入被吞/回环，看日志 pid 值即可定位（[MAC-TAP] 启动日志含 own_pid）。
- 跨屏甩触控板：日志应见惯性段（pid=WindowServer 非 0）进 Session tap 且 blocked=true
  被吞（只转发对端）→ 双滚消失。
- Win 光标到任务栏：Mac 无光标重显、无 hover 动画。
- 返回后光标落在手所在处（虚拟位置恢复）。

## 追加：mac→win"发起即归还"根因与修复（用户实测发现）
- 现象：win→mac 正常；mac→win 发起跨屏 1s 内被归还。Mac 日志：发起 TakeControl 后
  紧跟"对端归还控制"。
- 根因：Win 变 Sink 后注入光标落在入口边 = Win 自己的出口边（Mac 在右，入口=右边缘）。
  Win 端 on_sink_tick 判定"注入光标停在出口边 150ms 未动→归还"。mac 触控板跨屏要求
  边缘停 150ms 触发，跨过去手本来就是停的，再停 150ms 就触发归还。之前测双滚手一直动
  （光标动、计时重置）所以没暴露。
- 修复：arbiter.rs on_sink_tick 加 sink_was_away——必须【离开过出口边】后再停回出口边
  才算返回；on_peer_take 重置。共享代码 → **Win 端也要重编**。
- 验证方法：双机重编后：①mac 跨到 win 后停手 2s，不应被归还；②win 光标操作后拖回
  win 右边缘停 150ms，应正常归还；③RUST_LOG=ruiss_lib=debug 看 [MAC-MOVE] 确认
  跨屏后移动转发不断。
