# 2026-08-06 工作日志

## 跨屏双光标问题分析（未改代码）

胡先生反馈：Windows↔Mac 跨屏后，Source 端（发起跨屏的那台）鼠标还显示着，两个屏幕各有一个光标同步移动。

### 根因
Source 侧 `hide_cursor()` 不够健壮，光标隐藏被突破后重新显示，同时 Sink 侧注入的光标也在动 → 双光标。

### Windows 端（Source）
- `ShowCursor(FALSE)` 计数是 per-thread 的；光标可见性取决于鼠标所在窗口的线程计数
- Ruiss 在消费线程/tokio线程/钩子线程调 ShowCursor(FALSE)，不影响桌面/浏览器等前台窗口线程的计数
- `enforce_cursor_hidden_on_move()` 在钩子线程调用，同样只影响钩子线程计数
- 结论：鼠标在其他应用窗口上时，Ruiss 的隐藏无效

### Mac 端（Source）
- `NSCursor hide` 只调一次，没有类似 Windows 的"移动补藏"机制
- `hide_cursor()` 后紧跟 `warp_cursor()` 注入 MouseMoved 事件，可能触发系统恢复光标
- 后续真实鼠标移动放行给系统，也可能触发光标恢复
- 系统或其他 app 调 unhide 后无对抗

### 架构层面
当前设计是"隐藏光标 + 放行移动 + 转发"。光标隐藏是软约束（依赖 API 计数），一旦被突破就双光标。
